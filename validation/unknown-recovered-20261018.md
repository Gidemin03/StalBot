# UNKNOWN_RECOVERED: допуск новых предложений — 2026-10-18

Пользователь сообщил о пропуске «Очищенное вещество 07270» за 18 000 ₽
с причиной «Неизвестный результат прежнего BUY».

В рабочей БД, прочитанной без записи, найдена прежняя попытка
`717467dd1840475da038a52f5bd87553` с этим названием и ценой. Диагностика
сообщает отсутствие распознанного результата после ожидания около 3029 мс.
Это не доказывает ни успех, ни отказ покупки. Причина самого отсутствия
распознанного ответа в этой правке не устанавливалась.

Прежняя реализация исключала по всей истории UNKNOWN_RECOVERED совпадения
названия правила, цвета, заточки и полной цены, в том числе после перезапуска.
Этот ключ не является серверным ID и блокировал также новые предложения.

## Изменение

- Scanner, Runner и Store больше не исключают кандидатов по этому ключу.
  Старые UNKNOWN_RECOVERED сразу перестают блокировать новые предложения
  после перезапуска приложения; изменение рабочей БД не требуется.
- После UNKNOWN Runner запрещает следующий BUY до нового Search с изменившимся
  стабильным списком. UNCHANGED не снимает запрет. Обычные проверки актуальности
  строки, меню, цены и бюджета сохраняются.
- Восстановление не повторяет BUY. BUY_SENT/UNKNOWN/INSUFFICIENT продолжают
  транзакционно блокировать новые попытки; уникальный id нельзя использовать
  повторно. Неудавшееся восстановление не разрешает дальнейшую покупку.
- Резерв возможной стоимости остаётся однократным. UNKNOWN_RECOVERED не
  становится SUCCESS, не добавляет прибыль и сохраняется для аудита/сверки.
- Пояснения в UI, README, архитектуре и плане согласованы с кодом.

Старые тесты бессрочного исключения одинаковых предложений заменены проверками
допуска после обновления и перезапуска. Это изменение критерия поведения по
сообщению пользователя, а не изменение OCR baseline. Тесты также сохраняют
проверки запрета BUY до нового Search, незавершённой попытки, однократного резерва,
повторной финализации, очистки истории и миграции старой БД.

## Проверка

- 249 тестов без модулей `test_ui` и `test_date_picker` прошли:
  [журнал](unknown-recovered-20261018-core-final.log).
- 13 тестов восстановления повторно прошли после добавления проверки запрета
  повторного использования id: [журнал](unknown-recovered-20261018-recovery-final.log).
- Первичный общий запуск и найденные при разработке ошибки сохранены отдельно:
  [журнал](unknown-recovered-20261018-tests.log). Исправлены устаревшее ожидание
  UNCERTAIN_LOT и присваивание frozen Config в новом тесте.
- Tk-проверки не выполнены успешно: доступный Python не смог инициализировать
  Tcl/Tk (`Can't find a usable init.tcl`). Из финального прогона исключены оба
  модуля интерфейса; это не успешная проверка Tk.

Использован Python 3.12.14 из bundled runtime с `PYTHONPATH` на существующий
`.venv-benchmark/Lib/site-packages`: launcher `.venv-benchmark/Scripts/python.exe`
в этой сессии не смог создать процесс по сохранённому пути Python 3.12.0.
Окружения не изменялись. Все покупки в тестах — fake desktop и временные БД.
Полный OCR не запускался: распознавание не менялось. Реальные покупки не
запускались; работа изменения в игре пока не подтверждена.

Без серверного ID визуальное обновление и проверки меню не доказывают, что
одинаковое предложение является другим серверным лотом. Постоянный запрет
по внешним признакам сознательно снят; восстановление по-прежнему не повторяет
исходный клик BUY.
