# Переключение CPU / GPU — 2026-10-16

В UI добавлено поле «OCR»: CPU / GPU (DirectML). CLI принимает `--ocr-device cpu`
или `--ocr-device dml`; настройка `ocr_device` сохраняется вместе с остальными.
По умолчанию CPU, существующие пользовательские настройки не перезаписывались.
GPU использует одну DirectML-сессию для NAME с эффективным batch9; QTY/BUYOUT,
цвет и геометрия остаются на CPU. Размер группы выбора не меняется.
CPU batch сохраняется для обратного переключения.

При следующем Старт/Replay после смены устройства OcrSession закрывает прежний
ридер и его LRU до создания нового. Новый backend прогревается до захвата экрана.
Повторный запуск того же устройства сохраняет ридер и кеш. В строке подготовки
показаны устройство, batch и CPU для чисел; журнал и CLI содержат actual providers/options.

DirectML проверяется как первый активный provider, с `ORT_SEQUENTIAL`,
`enable_mem_pattern=False`, intra/inter threads 2/1. Runtime fallback на другую
сессию отключён; неподдерживаемые отдельные операции могут исполняться CPU provider.
Если DirectML недоступен/не загрузился, запуск сообщает ошибку; CPU выбирается явно.
Новые зависимости не устанавливались, модели и preprocessing не менялись.

## Проверки

- [231 unit/Tk-тест](gpu-switch-tests-20261016-final.txt): PASS, без пропусков.
  Проверены настройки, GPU batch9 в observe/live, вывод GPU в Tk, освобождение
  ресурсов, ошибка провайдера, закрытие старого ридера перед сменой и запрет
  скрытого CPU fallback. Игровой ввод в тестах заменён fake desktop.
- [Полная DML-интеграция](gpu-switch-dml-integration-20261016.json): PASS.
  NAME 170/170 при batch1/3/9, прежние проверки цвета/заточки, числового покрытия,
  UI-эталонов и 17 Replay. Все 612 сравнений Scanner с пустым/прогретым кешем
  совпали с вариантом без кеша; числовой OCR выполнялся заново.
- [Native CPU → DML → CPU и CLI](gpu-switch-native-20261016-b/report.json): PASS.
  На каждом устройстве все 170 кропов × batch1/3/9 совпали по полному Identity с
  первым CPU-проходом. Каждая смена создала новый ридер с пустым кешем; повторное
  использование того же устройства сохранило кеш. CLI CPU/DML отработали на
  обычном кадре с отдельными временными пустыми БД, результаты строк совпали.
- Наблюдения и стратегии всех 17 кадров из полной DML-регрессии совпали с
  предыдущим [CPU-отчётом](name-cache-integration-20261016.json).
- Профиль native-сессии подтвердил реальную работу GPU: 74500 событий узлов
  `DmlExecutionProvider`, 500 `CPUExecutionProvider`. Это доказательство исполнения,
  не оценка GPU-загрузки, FPS или перекрытия вычислений. Профилирование включалось
  только внешним проверочным скриптом; в рабочем приложении оно выключено.
- Хеши production-кода при native-проверке совпали с полной DML-регрессией.
  Labels, веса и исходный baseline сохранены.

Первый вариант вспомогательного native-теста ошибочно сравнивал полный Identity
с результатом разбора одного текста label. В четырёх строках NOT_VISIBLE штатный
визуальный признак разделителя сохраняет `upgrade=None`, а текст без разделителя
даёт 0. Исправлен только тест: используются прежние критерии разметки, а полное
Identity строго сравнивается между CPU/GPU. Неопределённая заточка, labels и baseline
не изменены. Различия записаны в `label_non_oracle_differences` успешного отчёта.

## Пользовательская проверка

Перед внедрением GPU пользователь предоставил [десятиминутный CPU-тест кеша](cache-live-user-20261016/README.md):
1416 попаданий, 246 промахов, 246/1000 записей, 0 вытеснений. Лимит остаётся 1000.
Последний показанный NAME округлялся до 0 мс; Search + ожидание составлял 444 мс.
Это один отображённый проход, не средние показатели всей серии.

Чтобы применить новый код, перезапустите приложение, выберите «GPU (DirectML)»
в поле OCR и запустите Replay/наблюдение. Обратно на CPU можно переключиться
после остановки без перезапуска приложения. При смене устройства первый проход
будет с пустым кешем; сравнивайте отдельно холодные и повторные проходы.

FPS игры, p95 полного цикла и польза GPU при данном 85% hit rate пока не измерены.
Реальные покупки агент не запускал. Игровые задержки, guards, каталог и бюджет
этим изменением не перенастраивались.
