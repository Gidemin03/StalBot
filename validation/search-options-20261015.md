# Настройки ожидания и повторного OCR — 2026-10-15

Пользователь подтвердил корректный Search и открытие меню без BUY; кадр показывает
688 мс Search + ожидание, NAME 286 мс, BUYOUT 18 мс, до решения 1008 мс.
Перепроверки выбранного лота выполняются позже и в этот показатель не входят.
В локальной трассе `data/diagnostics/search-033579725f274ddfb88d3ace81803a33/detail.json`
поля ещё старые на 328 мс после Search, изменились на 406 мс, снова изменились
на 469 мс, стабильны на 547 мс. Это дискретные захваты одного прогона, не точное
время серверного ответа. Вторая трасса search-53f26c4fe0e44ba7abda356c61653a9b:
старые поля на 391 мс, изменение на 454 мс, стабильность на 532 мс.

UI теперь сохраняет:

- «После Search»: по изображению (без OCR), `search_mode=changed` по умолчанию;
  фиксированная задержка, `static`. Первый режим уже использует изображение до
  Search как образец; отдельный дублирующий «шаблонный» режим не нужен.
- «Задержка, мс»: search_wait_ms 20–30000, по умолчанию 200; отсчёт после
  отпускания Search. В changed затем идут проверки изменения/стабильности;
  в static один захват и проверка чистого аукциона, без сравнения со старым кадром.
- «Повторный OCR лота перед покупкой»: revalidate_lot=true по умолчанию;
  false пропускает обе Scanner.row-перепроверки до выбора строки и после меню.

Настройки действуют для probe/live, блокируются на время работы и сохраняются
при Старт/Replay. Старые JSON получают прежнее поведение changed/true.
Настройки пользователя и рабочая БД не заменялись.

В static слишком короткая задержка может вернуть старый список. Отключение
повторного OCR может пропустить подмену лота до меню: шаблон меню не подтверждает
исходное имя и цену. Поэтому проверка чистого аукциона, шаблона меню, последнего
кадра перед BUY, актуального бюджета, отмены и результата остаётся. Меню проверялось
по шаблону изображения и раньше, без OCR. Геометрия сама по себе не доказывает,
что нажатие обработано игрой. revalidate_lot записывается в detail покупки/probe.

Проверки: **132 unit/Tk-теста PASS**, fake desktop и временные БД; без настоящего
ввода. Проверены static с одинаковым списком, одним захватом после задержки,
отменой и запретом анализа открытого меню, JSON/UI сохранение; ноль повторных
OCR при off, бюджет, правильная строка, UNKNOWN/история и отсутствие повторного BUY.
Полная [OCR-регрессия](integration-search-options-20261015.json) — PASS с прежним
baseline. Модели, preprocessing, labels/crops и пороги не менялись.

Новые опции static/off в игре ещё не проверены. Ускорение не объявляется измеренным.
Более узкая область сравнения/устойчивый порог — будущий эксперимент на записанных
кадрах с оценкой ложных изменений от анимации; не замена текущей проверки без тестов.
