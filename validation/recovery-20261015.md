# Восстановление аукциона и проверка лота после открытия меню

Изменён рабочий проект `C:\Users\demid\Documents\PythonProj\StalBot`.

## Поведение

- Убран повторный OCR до выбора строки. При включённой проверке осталось одно чтение
  после открытия меню; сравнение NAME/QTY/BUYOUT следующего кадра перед BUY сохранено.
- Изменение строки, пропавшее меню или изменившийся бюджет отменяют кандидата.
  После восстановления чистого экрана live начинает новый Search.
- Фиксированная пауза после уведомления и её поле UI удалены. Старое значение
  `post_result_delay_ms` игнорируется при загрузке настроек.
- Восстановление проверяет аукцион, меню и уведомления. До трёх кликов за 3 секунды:
  известный OK, найденный по шаблону OK неизвестного стандартного окна или Search
  для оставшегося меню. Интервал повторных кликов минимум 500 мс; BUY не повторяется.
- После UNKNOWN чистый экран разрешает UNKNOWN_RECOVERED: возможная цена однократно
  резервируется в локальном бюджете, совпадающий лот исключается из выбора и запрещён
  в Store. Остальные лоты доступны. Блокировка переживает перезапуск и игнорирует
  изменение строки/количества; одинаковые новые лоты требуют ручного разбора.
- При нестабильности Search даётся ещё одно окно settle_timeout_ms. Неустойчивый
  кадр не поступает в OCR; по повторному таймауту live начинает новый Search.
- Отрицательный sleep исправлен: оставшееся время считывается один раз и проверяется
  перед вызовом sleep. Раньше срок мог истечь между условием while и вторым чтением часов.

## Границы

В игре ещё нужно проверить закрытие меню через Search, доставку повторного OK и
поведение при задержанном обновлении списка. Проверка после меню не исключает
изменение строки между последним кадром и фактическим DOWN. Стабильность пикселей
не является подтверждением ответа сервера. Распознавание неизвестных окон ограничено
известным оформлением с modal_ok. Потеря фокуса, INSUFFICIENT, незавершённый BUY_SENT
и невозможность восстановить чистый экран по-прежнему требуют остановки.
