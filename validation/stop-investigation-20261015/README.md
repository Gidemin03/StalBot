# Остановки Search 2026-10-15

Проверены приложенное видео `Desktop 2026.10.15 - 18.45.19.14.DVR.mp4`,
`data/errors.log` и последние три Search-диагностики:
`search-3fb56377b2d849cc8cdfdebb00605152`,
`search-08dfcb86bf354d3992aa054647b00f19`,
`search-9e096b49da3b463bb8f699416471366e`.

У всех трёх результат UNSTABLE, first_change_ms=null: первые четыре строки
не изменялись, но итоговый полный кадр отличался. У последней диагностики
пиксельное сравнение NAME/QTY/BUYOUT показывает изменения исключительно строки 5:
11922 / 63 / 11193 отличающихся значений каналов соответственно.
Последняя ошибка — отказ подтверждения обновления Search, без связи с UNAVAILABLE.
Это объясняет последние три остановки, а не все исторические ошибки журнала:
ранее в нём встречается также смещение курсора перед кликом.

Исправление: если триггер четырёх строк не обнаружил изменения к половине
таймаута, перейти к наблюдению всех девяти. Стабильность и финальный полный кадр
проверяются штатно, без нового Search или продления таймаута. Нестабильный список,
потеря фокуса и неизвестный результат BUY по-прежнему останавливают ввод.
Строка состояния Tk резервирует место перед размещением расширяемых вкладок,
чтобы причина остановки оставалась видна в невысоком окне.

Регрессии: стабильное изменение нижней строки принимается; непрерывно меняющаяся
нижняя строка отклоняется; ошибка отображается в окне 1080×760 после завершения
рабочего потока. Все проверки ввода используют fake desktop, покупки не запускались.
