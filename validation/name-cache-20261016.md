# Внедрение точного NAME LRU — 2026-10-16

В рабочий UI и CLI Replay добавлен `CachedNameReader` поверх прежнего CPU Reader.
По умолчанию 1000 записей; настройка `name_cache_capacity` в UI/JSON и
`--name-cache-capacity` в CLI, 0 отключает кеш. GPU, preprocessing, ввод и игровые
guards не менялись. Для нового кода нужно закрыть приложение и запустить заново.

Ключ — исходные RGB-байты и форма кропа, значение — неизменяемая Identity.
Кеш привязан к одному Reader/потоку, переживает Старт/Replay, очищается при закрытии.
Прогрев обходит кеш. Цены, количество, каталог, бюджет и решения читаются/вычисляются
заново. Счётчики в UI относятся к текущему запуску, включая проверку NAME в меню;
итог попадает в существующий журнал событий и CLI JSON.

## Проверки

- [Полная интеграционная регрессия](name-cache-integration-20261016.json): PASS.
  Исходный native OCR baseline сохранён независимым. NAME 170/170 при batch 1/3/9,
  цвет/заточка, числовое покрытие и UI-эталоны прошли прежние критерии.
- Полный Identity с кешем совпал с native OCR на всех 170 кропах для каждого batch,
  с пустым кешем и при повторе. 17 кадров × 18 сочетаний batch/группа/критерий ×
  2 состояния кеша = 612 сравнений выбранного лота и всех прочитанных строк без
  расхождений. Числа в этих Scanner-прогонах действительно распознавались заново.
- [217 unit/Tk-тестов](name-cache-tests-20261016.txt): PASS, без пропусков. Включают
  точность ключа, изменение одного пикселя/формы, noncontiguous RGB, LRU/переполнение,
  выключение, прогрев, owner thread, повторные сессии, ошибки native, обновление
  цены/количества/каталога/бюджета, UI-настройку и счётчики.
- [CLI smoke](name-cache-cli-20261016.json): PASS для capacity 1000 и 0, одинаковые
  наблюдения на обычном кадре и отдельные временные пустые БД. Хеши production-кода
  после проверок совпали с записанными при запуске полного OCR.

## Время NAME на этом прогоне

| Batch | Без кеша, 170 кропов | Пустой кеш в начале | Полный повтор |
|---|---:|---:|---:|
| 1 | 5269 мс | 2245 мс | 1,48 мс |
| 3 | 6456 мс | 2689 мс | 1,56 мс |
| 9 | 9592 мс | 4308 мс | 1,27 мс |

Это одиночная интеграционная серия, не новый контролируемый latency-benchmark.
Модели заранее прогреты. В наборе 75 уникальных RGB-кропов на 170 строк, поэтому
даже первый проход получает попадания. На повторе все 170 запросов попали в кеш;
JSON-счётчики повторной фазы накопительные, включают первый проход.
Числовой OCR, захват экрана, Search и BUY в эти времена не входят.

75 записей хранят 910575 байт пикселей; `pixel_bytes` не включает Python-объекты
и память моделей. Примерно 12 МиБ для 1000 записей — оценка по прототипу.
1000 — начальная настраиваемая ёмкость, не найденный экспериментом оптимум.

Живые hit rate, вытеснения и влияние на полный цикл с игрой ещё не измерены.
Реальные покупки в проверках не запускались; рабочие БД, настройки, модели,
датасет и baseline этой реализацией не заменялись.
