# OCR баланса, 2026-10-19

Добавлен отдельный `stalbot/balance.py`, не меняющий OCR NAME/QTY/BUYOUT.
Рабочий API: `read_balance(reader, frame) -> Number`; принимает штатный Reader
или CachedNameReader, выполняется на его потоке. Изображение — uint8 RGB
1920×1080, для сохранённых Replay также 1920×1081.

Область `(1000, 804, 1388, 826)` охватывает строку счёта внизу планшета без рамок.
Увеличение ×3 + Otsu и Tesseract rus+eng, PSM 7, без whitelist цифр.
Принимается только полная строка `Счет: <целое> руб.` / `Счёт: <целое> руб.`.
Группы тысяч должны иметь три цифры, ноль допустим, знаки и дроби запрещены.
Не выполняется замена букв на цифры или извлечение числового фрагмента.
Значение ограничено знаковым 64-битным целым для SQLite; всё сомнительное
возвращает `Number('AMBIGUOUS', None, raw)`.

## Проверка

`check.py` использовал рабочий `read_balance` и настоящий `CachedNameReader(Reader)`
на 6 шаблонах, 13 hard_cases и 17 processed: **36/36 полных строк приняты**.
Все 36 кропов сверены визуально по `contact-sheet.png`; значения совпали.
Это только **три разных значения**: 2 246 604, 2 377 082 и 2 384 070.
Некоторые кадры дублируют состояния друг друга; 36 не означает 36 независимых балансов.
Результаты с путями, SHA-256 входов, raw и временем — `production-results.json`.
NAME-кеш остался пуст; смена whitelist после QTY не мешает чтению счёта.

Время полного `read_balance` без захвата экрана и загрузки моделей:
минимум 25,33 мс, среднее 28,84 мс, максимум 36,18 мс.
Это одна последовательная офлайн-серия, не измерение скорости в игре.
`probe.py`/`probe.json` и отдельные `crop-*.png` — предварительная проверка ROI.

Шесть unit-тестов прошли:

```powershell
.\.venv-benchmark\Scripts\python.exe -m unittest discover -s tests -p test_balance.py -v
```

Покрыты ноль, пробелы Unicode, полная строка, отказ при повреждённых группах,
неполном тексте, отрицательных/дробных значениях, переполнении, форма и тип кадра,
поток Reader, закрытый Reader, свежий OCR через кеш и сброс whitelist.
Никакого ввода в игру, изменений датасета, модели или рабочей БД не было.
Запуск Python потребовал sandbox escalation: обычный запуск не мог создать
процесс базового Python312. Тесты после разрешения выполнились успешно.

## Ограничения

Нет реальных примеров баланса 0, менее миллиона и большого количества разрядов;
парсер проверен на них unit-тестами, визуальный OCR — только на трёх суммах выше.
Рамки/масштаб интерфейса фиксированы. Корректный синтаксис не исключает ошибку цифры.
Чтение само по себе не доказывает покупку: Runner должен читать только подходящий
экран и проверять стабильность на разных кадрах, особенно после UNKNOWN.
Промежуточное снижение при отказе может сохраняться около 0,5 с по наблюдению
пользователя; подтверждать SUCCESS по первому такому кадру нельзя.
Повторная OCR-проверка и задержки серверных возвратов в живой игре здесь не проверялись.
